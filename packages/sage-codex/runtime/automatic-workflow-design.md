# Automatic Sage coordination in Codex

This proposal defines the first stage of #88: automatic coordination with manual merging. Autopilot stays off.

## Owner experience

The owner installs and trusts the reviewed local hooks, then enables Sage for one project and session. The current chat becomes the chief. It shows capability status before accepting work.

The chief designs the task and records a brief. Native Codex subagents receive saved roles and briefs. Independent reviews and QA return structured reports. The chief stops at a reviewed PR for the owner to merge.

Status shows the mode, task, occupied slots, open questions and missing capabilities. Unsupported activation gives a reason; instructions alone never count as enforcement.

## Records and rules

Core owns project configuration, session epochs, tasks, immutable briefs, atomic assignments, bound runs, report receipts and exact-head review cycles. Codex owns trusted event decoding and installed transport. Native permissions remain in force.

Only verified owner input changes mode. Missing identity, unsupported events and capture gaps refuse protected work. Only the chief starts leads; bound leads start permitted children within shared limits.

A failed start retains its reservation until authoritative failure evidence permits release. Duplicate events are idempotent. Conflicting identities refuse. Late events cannot release newer assignments.

Reports must match their task, run, assignment and brief. Report acceptance and capacity release are separate. A stopped child does not prove success. New commits invalidate earlier clean cycles.

The latest owner direction requires parity with Claude. Claude's mode hook turns Sage and autopilot off and restores direct chief edits. That transition does not itself interrupt native agents. Codex must match this behavior, rather than add automatic interruption on mode-off.

The earlier interruption proposal is superseded by parity. Explicit owner cancellation remains distinct from mode-off. Restart and compaction recovery must preserve saved identities and work; the implementation must derive their exact rules from Claude and native lifecycle evidence. Children never merge.

## Parity audit

Before implementation, map Claude's activation, chief authority, task routes, role and child limits, briefs, reports, review cycles, repair, merge gates, off behavior and recovery. Record each as enforced code, instructions, or live verification. Match user behavior through Codex-native transport; do not label a prompt-only rule as enforced.

The full target includes Claude's gated autopilot. Coordination with manual merging is the first delivery stage, not a reduction of the parity target. Provider model names and native transport remain provider-specific.
